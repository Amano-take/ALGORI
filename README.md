## モジュール説明
- GameModule
ゲームの動作に関するモジュール群。
    - Master:　実際に動かす部分。set_boardメソッドによってPlayOutが可能。Numba等の高速化により、初期状態から1secあたり1000回ほどのPlayOutが可能
    - Player:　プレイヤー部分。賢いplayerはこのplayerを継承し作成することとする。特にPlayOutで用いるのは、出せるカードの内ランダムに出すRandomPlayer.
    - Rule：　 UNOのルールを管理する。実際には場のカードに対して、出せるカードを１出せないカードを０としたone-hot vectorを管理したり、最後のスコア計算を行う。
    - Card:　カードクラスを格納。np.ndarray[object]は遅いっぽいのでなるべく使わない。可視化する際にprint(Card(i))で可視化する。一応比較や等号判定も可能。
    - Probability Model: あるカードをある枚数持っている確率を計算する。このモデルによって相手の持っているカードとしてあり得るものを生成可能（get_palyer_card)
    - MonteCarloSingle: 次の順序で最善手を求める。相手の行動を観察し、ProbabilityModelによって適切に相手の持っているカードをランダムに生成（例えばRed5でパスしたならば、Blue5やRed0を持っていないように）。
          その後、Masterクラスによってそれぞれの出せるカードを出した状態でのPlayOutを行い、(自分のスコア、相手1のスコア、、、)の配列を得る。その後この配列をscores2scoreによって一つの値にする。
          そうして平均スコアが高かったカードを実際に場に出す。発展としてモンテカルロ木を想定していたが間に合わず。
    - scores2score:  評価関数にあたる部分。今回は順位が大事であることから順位を大きく加味してスコアリングを行った。
- 感想
  予選の決勝（1位通過で本選）で2位敗退。実装が後々のことを考えておらず、最後に近づくにつれバグの修正まみれになってしまいあまり開発が進まなかった。また、Probability ModelとALGORI運営が用意した真のMasterがかみ合わず実装を断念、
  簡易的なものになってしまった。
  Master部分くらいはPythonではなくそのほかのNim等の高速な言語を使用するかNumba化を前提とした実装にすべきであった。大体合計2000回ほどのplayoutという少なさが原因なのかもしれない。
  反省点が多く存在する結果となってしまったが、ルールベース以外のAIに挑戦するいい機会となった。次に活かしたい。
